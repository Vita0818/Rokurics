**审计日期：** 2026-06-30
**排查对象：** iPhone 客户端手动点击“上传音频”按钮后 UI 显示“上传失败”故障

## 1. 决策层与状态拦截分析 (Early Return / Decision Blockers)

在调用 [RecordingUploadCoordinator.swift:uploadAndWaitWithActiveTrace(...)](file:///Users/vita/Vitemis/Vela/Rokurics/Rokurics/RecordingUploadCoordinator.swift#L699) 后，系统会立即通过 `evaluateRecordingAudioUploadDecision` 评估状态。若判定不应发起物理上传，会抛出 Fail 决策导致 UI 直接呈送失败状态。Codex 需核对以下代码逻辑：

### 1.1 本地音频不可用或未就绪
* **代码定位**：[StudyLibrarySyncModels.swift:L703-712](file:///Users/vita/Vitemis/Vela/Rokurics/Rokurics/StudyLibrarySyncModels.swift#L703-L712)
* **决策分支**：若 `localAudioState` 为 `.missing`、`.unknown`、`.unreadable` 或 `.deleted`，返回 `fail`，UI 映射为“上传失败”。
* **Codex 诊断动作**：
  - 检查 iPhone 沙盒下录音文件是否存在及大小。
  - 检索 `UploadFlightRecorder` 是否打印了 `audio_file_missing` 或 `audio_file_empty_or_missing`。
  - 检查是否由于录音尚未完全落盘/写入完毕，导致 `AudioFileStore` 读取的大小为 0。

### 1.2 对等端音频哈希冲突 (Conflict / No-Overwrite)
* **代码定位**：[StudyLibrarySyncModels.swift:L777-L778](file:///Users/vita/Vitemis/Vela/Rokurics/Rokurics/StudyLibrarySyncModels.swift#L777-L778)
* **决策分支**：若 `peerAudioState` 为 `.different`（对等端已存在不同哈希或大小的音频），返回 `fail` (原因 `"peer_audio_conflict"`)，UI 显示“上传冲突”或“上传失败”。
* **Codex 诊断动作**：
  - 检查 Mac 端是否已经通过其它设备同步过同名但哈希不同的录音。
  - 为防音频被非法覆盖，内核此时硬性拦截上传请求。

### 1.3 账本状态 Fatal (Fatal Ledger Failure)
* **代码定位**：[StudyLibrarySyncModels.swift:L751-L755](file:///Users/vita/Vitemis/Vela/Rokurics/Rokurics/StudyLibrarySyncModels.swift#L751-L755)
* **决策分支**：SQLite 账本中已存在该 Job 且状态为 `.fatalFailed`。
* **Codex 诊断动作**：
  - 读取 `jobStore` 的错误日志 (`lastErrorMessage`/`lastErrorCode`)。
  - 需要在 SQLite 账本层清除致命错误 Job 状态，才能重新触发手动上传。

## 2. 物理网络与验签拦截分析 (Connection & Verification Blockers)

若决策通过并进入物理上传路径，以下步骤最容易因边界异常导致抛出 Error 归入 `catch` 失败分支：

### 2.1 配对状态判定 (`settings.isPaired` 为 `false`)
* **代码定位**：[RecordingUploadCoordinator.swift:L825-L840](file:///Users/vita/Vitemis/Vela/Rokurics/Rokurics/RecordingUploadCoordinator.swift#L825-L840)
* **故障点**：虽然网络连接通过，但设备未配对。iPhone 直接 return 并置 UI 状态为 `failed`。
* **Codex 诊断动作**：
  - 检查 iPhone 侧 `settings` 实例的 pairing state。
  - 确认 Keychain 中的 pairing secret 及 MacIdentity 的指纹信息是否被误重置或抹除。

### 2.2 服务端验签拦截 (`RequestVerifier` 拒绝)
* **代码定位**：[SecureLocalHTTPSServer.swift:L295](file:///Users/vita/Vitemis/Vela/Rokurics/RokuricsMac/SecureLocalHTTPSServer.swift#L295) (以 start 路由为例)
* **故障点**：Mac 端收到请求后调用 `requestVerifier.verify` 进行身份鉴定，若未通过则在 HTTP 响应中返回 `.rejected(reason)`。
* **主要怀疑点**：
  - **时钟偏差 (Clock Drift)**：双端设备系统时钟不一致，导致验签中 Nonce/时间戳拦截器（一般容忍度在数分钟内）将其判定为重放请求或无效请求，返回 400/403。
  - **密钥错配**：局域网认证密钥错配，HMAC 散列无法对齐。

### 2.3 分块上传传输超时/中断
* **代码定位**：[RecordingUploadClient.swift:L758-L781](file:///Users/vita/Vitemis/Vela/Rokurics/Rokurics/RecordingUploadClient.swift#L758-L781) (Chunk 上传循环)
* **故障点**：在循环发送 Chunk 期间出现 `NWConnection` 断开、网络超时，或 Mac 端因磁盘爆满写入中断（`recordingFileStore.appendResumableAudioChunk` 报存储失败并返回 500）。

## 3. Codex 精准定位排查命令

Codex 在接入时，可通过以下 Grep 及日志指令锁定底层故障原因：

```sh
# 1. 检查上传决策流中的 Early Return Blocker 日志
rg "uploadCoordinatorSkippedWithReason|audioConflictDetected|uploadConflictDetected"

# 2. 检查本地音频文件哈希与大小诊断
rg "uploadCoordinatorFileSizeChecked|audio_file_empty_or_missing"

# 3. 检查验签与网络传输层的失败详情
rg "uploadRouteHandlerResponded|audioReceiveFailedWithReason"

# 4. 打印 jobStore 账本中是否存在致命失败记录
rg "ledger_read_failed|fatal_ledger"
```
