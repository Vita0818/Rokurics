## 1. 项目整体理解与架构概述

Rokurics 项目是一个跨 iPhone/macOS 平台的本地局域网录音同步及智能转写处理系统。其系统架构核心分为两端，由 iPhone 发起录音并作为 HTTPS 客户端进行上传同步，由 Mac App 作为 HTTPS 服务端接收录音并调用 Whisper.cpp、Note Coordinator 等底层组件完成 AI 转写与笔记生成。

系统目前正在经历重大的 **Canonical 四域同步内核（Connection、Transfer、Sync、File）** 重构。虽然当前生产及 Release 模式下依然强制 fallback 到旧的 `oldKernel` 逻辑，但该四域内核在代码级已经完成了全部的 Readiness Gate 收口。

- **连接域 (Connection)**：由 iPhone `StudyLibrarySyncCoordinator` 和 Mac `SecureReceiverService` 共同引用的 [CanonicalConnectionRuntime](file:///Users/vita/Vitemis/Vela/Rokurics/RokuricsShared/SyncCore/CanonicalConnectionRuntime.swift) 主导，负责局域网内的存活探测、心跳信封和 `syncRequested` 指示。
- **传输域 (Transfer)**：[CanonicalTransferRuntime](file:///Users/vita/Vitemis/Vela/Rokurics/RokuricsShared/SyncCore/CanonicalTransferRuntime.swift) 状态机主导，实现了 byteMonotonic 递增、wrong-offset resume 恢复机制以及传输成功后的 `CanonicalTransferFinalizeProof`。
- **同步状态真相域 (Sync Status Truth)**：[CanonicalStatusTruthRuntime](file:///Users/vita/Vitemis/Vela/Rokurics/RokuricsShared/SyncCore/CanonicalStatusTruthRuntime.swift) 主导，强制要求 UI 状态的 completed/peerVerified 仅能从强 Proof 链路投影，阻断了 metadataOnly 或 receiveRecordOnly 等软事实的强推。
- **文件域与防卡死 (File/No-Freeze)**：通过 [CanonicalAsyncDiagnosticsWriter](file:///Users/vita/Vitemis/Vela/Rokurics/RokuricsShared/SyncCore/CanonicalAsyncDiagnosticsWriter.swift) 及后台 actor，强制将重度 IO/哈希/扫描逻辑移除主线程，避免 UI 冰冻。
