FINDINGS:
在“点击按钮 -> 开始上传 -> 上传成功 -> UI变化”这套全链路中，发现了一个严重的状态覆盖漏洞（Stale Value Capture）：
1. 在 `RecordingUploadCoordinator` 的 `uploadAndWaitWithActiveTrace` 方法执行前，获取的 `metadata` 参数是值类型 `struct`，内部保存了旧状态（如 `local_only`）。
2. 在旧内核（约 1077 行）及新内核 fallback 兜底（约 1436 行）执行成功后，底层真实数据已更新为 `.uploaded`（`recordingManager.updateUploadStatus`）。
3. 但紧接着调用的 `setActiveStatus(nil, for: metadata)` 使用的是原先旧的 `metadata`，导致 `@Published displaySyncStateByObjectID` 这一用于覆盖卡片显示状态的字典，捕获并保存了旧状态。
4. UI 刷新时，`canonicalDisplaySyncState` 读取到了错误的 override，使得成功上传的录音在界面上仍然呈现为未上传状态。
