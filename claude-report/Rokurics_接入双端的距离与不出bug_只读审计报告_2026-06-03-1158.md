## 2. 本轮新增的"执行级影子"为什么是稳的（证据）

### 2.1 真执行，但只进隔离临时根

- 工厂在执行影子模式下构造**真实** `IPhoneCanonicalShadowFilePort`（`isDryRunOnly=false`，真做原子写/containment/回滚/hash），但根目录是 `temporaryDirectory/RokuricsCanonicalExecutionShadow/iPhone/<UUID>`（`IPhoneCanonicalShadowPortFactory.swift:70-88`）。
- 非执行模式回落到 dry-run 端口（`:64-66/80-82`）。

### 2.2 传输发送被强制抑制（抛错）

- `IPhoneCanonicalShadowTransportPort`：`realNetworkExecutionEnabled=false`，`sendRequest(...)` 直接 `throw networkExecutionSuppressed("iphoneShadowTransportSendSuppressed")`（`:11/34-35`）。即影子能构造签名信封做投影，但**任何真发送都会抛错**——无网络副作用。

### 2.3 真实数据根被双重硬拒绝（关键安全闸门）

- `CanonicalExecutionShadow.swift` 的 `validatedShadowRootURL()` 会抛：
  - `productionMutationAttempted("shadowProductionRootRejected")`（`:36`）
  - `productionMutationAttempted("shadowRootInsideProductionRootRejected")`（`:53`）
  - 非 file URL → `pathEscapeRisk`（`:43`）
- 即**执行影子在结构上无法指向真实录音根或其子目录**——这是"不动用户数据"的硬保证。

### 2.4 影子的 upload/apply 端口也 fail-closed

- `CanonicalShadowApplyPort`/`CanonicalShadowUploadPort`（`CanonicalExecutionShadow.swift:651/882`）对真实变更抛错，如 `shadowTombstoneMarkerDisabled`(`:210`)、`shadowMetadataBytesDisabled`(`:261`)。

### 2.5 默认关闭 + 细粒度开关

- 接缝守门：`canonicalShadowMigrationConfiguration.isEnabled`（默认 false）+ 新增 `canonicalSingleDomainShadowConfiguration`（单域影子，如只跑录音 metadata），两者默认关（`StudyLibrarySyncCoordinator.swift:2107-2148`）。
- 模式枚举本身含 `blockedProductionExecute / blockedExecutionShadowWrite / blockedExecutionShadowUpload / blockedExecutionShadowApply`（`CanonicalShadowMigration.swift:19-22`）——用类型把"还不能做的事"标成 blocked。

→ **综合：当前即使有人手滑开启影子，也碰不到真实数据、发不出网络、改不动对端**；默认状态对生产零风险。这正是"重点不出 bug"的工程姿态。

## 3. 当前状态的 bug 风险评估：基本为零（但有 1 个轻微项）

- ✅ 生产路径默认全部走旧内核；影子默认关、可回退。
- ✅ 真执行只进临时根；真实根硬拒；网络发送抛错；变更端口 fail-closed。
- ✅ 文件端口有回滚检查点 + 原子写；大量执行影子/回滚/等价测试。
- ⚠️ **轻微（仅磁盘、非数据）**：执行影子每次按 `…/RokuricsCanonicalExecutionShadow/<UUID>` 建新临时目录，**未见 app 接缝里显式清理**（测试里 `removeItem` 清理，app 侧没看到）。若在真机长期开启执行影子，临时目录可能累积占用磁盘（系统临时区，OS 可能回收）。**开启执行影子前，建议补一个"运行后回收临时根"的清理**。

## 4. 走完剩余 3 步时的 bug 风险点（按危险度，供你把关）

**第 5 步（喂真实只读数据副本）——低-中风险**
- 风险：复制真实录音/metadata 时若用错方向/路径，可能动到原件。
- 闸门：复制必须只读取原件、只写入隔离副本；复制后校验副本 hash==原件；任何写仍走临时根。

**第 6 步（真实只读传输探针）——中风险（第一次真上线网络）**
- 风险：探针若不慎触发写路由（如 `/sync/apply-metadata`、`/upload-*`），会在 Mac 建 receive 记录/改状态。
- 闸门：只允许幂等只读路由（如 `/sync/inventory`、`/fingerprint`、`/health`）；复用现成 TLS pinning + HMAC（红线：`manifestHash` 不当鉴权）；Mac 侧加"影子请求不落库"断言。

**第 7 步（受控真实根执行 + 切主）——最高风险**
- 风险：真实写盘/上传的崩溃安全（写一半断电）、回滚正确性、重试幂等、metadata/audio 原子替换与 receive.json 一致性。
- 闸门（建议全部满足才允许单域上线）：
  1. 执行影子在**真实数据副本**上与旧内核**逐字节等价**；
  2. **故障注入**下回滚演练通过（写中断/权限失败/磁盘满）；
  3. 重试幂等性证明；
  4. 先只放**一个最小且可逆的域**（建议录音 metadata），观察期后再扩；
  5. 护栏全绿（approval + rollback + dryRun 等价 + 执行影子等价）。

**UI 读路径切换——中风险**
- 风险：UI 改读 canonical 投影后，状态/显示回归。
- 闸门：先并行展示对照，差异为 0 再切。

1. **现在（零风险）**：真机依次开 `diagnosticsOnly → shadowReadOnly → 单域 executionShadowDryRun`，确认决策分歧=0、执行影子结果干净；顺手补第 3 节的临时根清理。

3. **第 6 步**：加真实只读传输探针（仅幂等只读路由）。
