## 0. 一句话结论

**学习库是迄今最完整的域模板：写侧（域专属真实写端口 + commit + NoCommit）＋读侧（读等价影子 seam）＋域矩阵（带退役安全护栏）一应俱全——它补上了我此前反复点名的"读侧那一半"。** 但要精确：**它仍默认关、未在 app 注入/启用，且"读侧"目前是影子等价比对、不是真正切换 UI 读 canonical**——`StudyLibraryStore`/学习库 UI 一行没改、仍读 legacy。所以"整个写完了"= **整条迁移+校验脚手架写完（含读侧影子），默认关、未落地**，而非"app 已在用 canonical 跑学习库"。生产风险仍为零。

## 2. 但"读侧"是影子等价、不是真切换（关键澄清）

- **读侧 seam 只被同步协调器/服务调用**（`StudyLibrarySyncCoordinator.swift:2051/3127-3138`、`SecureLocalHTTPSServer.swift:3458/3944-3955`），名为 `recordCanonical…ReadSideSeamIfEnabled`，默认关、只落诊断。
- **它做的是比对**：`evaluate(...)` 同时构造 `legacySnapshot`（legacy manifest→adapter）与 `canonicalSnapshot`（canonical manifest），交给 `CanonicalLibraryMetadataReadSideCutoverEvaluator.evaluate` 产出等价/分歧结果（`IPhoneLibraryMetadataReadSideSeam.swift:30-62`）。
- **真实读模型未动**：`StudyLibraryStore`（iPhone/Mac）grep canonical **零命中**——UI/Store 仍纯 legacy 读；本轮 git status 也无 `StudyLibraryStore`/学习库 UI 改动。

→ 读侧目前 = **"canonical 读会得到什么 vs legacy 读得到什么"的影子等价校验**，不是"把 UI 切到读 canonical"。这对安全是对的（先证等价再切），但要清楚：**学习库的读路径尚未真正迁移。**

## 3. 写侧也未启用（默认关、未注入）

- 真实写端口 `IPhoneLibraryMetadataRealApplyPort` 默认 `isDryRunOnly = true`（无参 init，`:22`）；commit 执行器虽默认引用 `IPhoneLibraryMetadataRealApplyPort()`（`:18`），但那是**禁用实例**，commit 对 dryRun 端口 fail-closed。

## 5. 后续域是否按此模式继续？——是，且这是目前最佳模板

**应继续，并以学习库为标准模板**，因为它比早期域多了两件关键东西：**读侧影子 seam** 和 **域矩阵退役护栏**。每个域复制这套五件套：
1. 域专属真实写端口（production root + `allowProductionRootWrites`，默认禁用 + `rootEscape` 防逃逸 + 原子 + 回滚）；
2. NoCommit 执行器；
3. Commit 执行器（前后置校验/幂等/回滚/故障注入/副作用白名单）；
4. **读侧影子 seam（读等价比对）**；
5. 全部经 **`CanonicalMigrationDomainMatrix`** 管理阶段与退役护栏。

**但强烈建议：先把学习库这一个域真正"落地"，再批量复制。** 否则会继续堆"完整但永不启用"的脚手架（现在连读侧影子都加上了，规模更大）。

### 其它域要补的差距
早期域（录音 metadata、生成产物、tombstone）**还没有读侧 seam**（只有 library 有）。在大规模推进前，应把读侧 seam + 域矩阵**回填**到这些已建域，让它们对齐学习库模板。

## 6. 经验 / 教训

1. **读侧那一半终于被建出来了——把它定为每个域的标准阶段。** 学习库的 ReadSideSeam + 域矩阵的 `retiredWithoutReadSideCutover` 护栏，正好把"commit 写完≠迁移完成、不切读不许退役"变成机器强制。**以后每个域都必须过这道。**
2. **"整个写完"仍止步于"影子已校验"，不是"已启用/已切读/已退役"。** 真正未知的三件事——真机行为、`StudyLibraryStore`/UI 的真实读切换、legacy 退役——对学习库仍未做。**模板完整 ≠ 迁移被验证。**
3. **最有价值的下一步是"把学习库一路打到底"**：① 注入启用 production-root 写端口 + 真机 `canaryCommit`(N=1)；② 开读侧影子，确认真机读等价=0；③ 做**真实读切换**（让 `StudyLibraryStore`/UI 读 canonical 投影，带并行对照 + 差异=0 才切主）；④ 观察期；⑤ 经域矩阵护栏退役 legacy。**只有走完这五步，试点才从"完整模板"升级为"已验证迁移"，并把真实风险（UI 读回归、真机表现）暴露在最小安全域上。**
4. **真实读切换是唯一要动"真实读模型"的步骤（`StudyLibraryStore`/UI 至今未动），也是读侧最易出回归的一步。** 每个域都要把它当成独立的、带闸门 + 并行对照的步骤来做，别和写侧混在一起。
5. **域矩阵是好东西，让所有域都走它**；逐步淘汰各域散落的 ad-hoc 配置（配置收敛诉求本轮在矩阵层得到回应）。
6. **节奏不变**：一次一个域、默认关、影子先于启用、写侧切换先于读侧切换、退役最后且过护栏。
