## 2. Commit 接口"可用性"被真实实现证实（本轮关键）

上轮我标注"Commit 接口就绪、真实性待证"。本轮 `IPhoneRecordingMetadataCutoverExecutor`（`actor : CanonicalRecordingMetadataCutoverExecutor`）给出了**严谨的真实实现**，说明协议确实承载得起一次安全提交所需的全部要素：

- **前置/后置校验**：objectID 匹配、canonical/local/peer hash 齐备、无未解决冲突、`modifiedAt` 方向、tombstone 状态、bridgeHint 匹配（`:276-323`）；提交前 `verifyPrecondition`、提交后 `verifyPostcondition`（`:74/135`）。
- **幂等**：`committedActionIDs` 去重，重复提交返回幂等成功（`:56-66`）。
- **回滚 + 致命阻断**：`rollbackRecordingMetadata` 调 `applyPort.rollbackApply`，失败置 `rollbackFatalBlocker` 阻断后续提交（`:174-230`）。
- **副作用白名单**：录音 metadata 提交只允许 `metadataApply` / `applyMetadata` 路由 / 诊断写；文件写/上传/tombstone/冲突等一律拒绝并判部分提交失败（`:326-338`）。
- **内建故障注入**：`CanonicalRecordingMetadataCommitFailureInjection` 覆盖 preconditionMismatch / transportFailureBeforeSend / applyFailureBeforeCommit / applyFailureAfterPartialCommit / rollbackFailure / postconditionMismatch——**正好是回滚演练所需的能力**。

→ 这是一份**高质量、可作集成参照**的实现；协议被它压过后，可判定"Commit 接口稳定可用"。

## 3. 安全：仍然零生产风险（结构性挡住真实数据）

- **不存在写真实根的 apply 端口**：双端 `CanonicalProductionApplyPort` 只有两种模式 `disabled`(isDryRunOnly=true) 与 `fakeInMemory`(写内存)（`IPhoneCanonicalProductionApplyPort.swift:129-130`、Mac 同构）。**没有任何绑定 `AudioFileStore`/`MacRecordingFileStore` 的真实端口。**
- **Commit 执行器对 dryRun 端口 fail-closed**：`guard !applyPort.isDryRunOnly else { return .failure(...) }`（`:81-83`）——只有非 dryRun 端口才提交，而非 dryRun 的唯一选项是 `fakeInMemory`，所以提交只落内存。
- **Commit 执行器未接入 app**：`IPhone/MacRecordingMetadataCutoverExecutor` 在 app 同步/接收/入口**零调用**（grep 确认），仅测试/Facade 可达。
- 默认仍全关：`makeDisabledPortSet()` 为默认端口集；NoCommit app seam 由 `canonicalV8CutoverAppSeamConfiguration = .disabled` 守门（上轮已核）。

→ 真实用户数据**结构性碰不到**：没有真实根端口 + Commit 未接线 + 默认关。提交路径目前只能对内存假存储跑（适合测试/回滚演练）。

## 5. 下一步方向

**唯一真正缺的"真实写"是一个 apply 端口；Commit 执行器与协议已就绪，故剩余工作被很好地隔离成"一个适配器 + 接线 + 过门"。**

1. **现在就能做（零风险）**：用新 Commit 执行器 + `fakeInMemory` apply 端口跑**故障注入回滚演练**，逐个验证 `CanonicalRecordingMetadataCommitFailureInjection` 各失败态都能干净回滚、幂等成立、副作用白名单生效。今天即可测。
2. **实现真实根 apply 端口（核心剩余件）**：新增 `CanonicalProductionApplyPort` 的真实实现，iPhone 绑 `AudioFileStore`、Mac 绑 `MacRecordingFileStore`，做 metadata **原子替换 + 回滚检查点（提交前存旧字节）**，强制 `isInsideRoot`，`isDryRunOnly=false`。这是唯一让 Commit 真正落盘的缺口。
3. **接线到 app（默认关、过全门）**：把 Commit 执行器 + 真实 apply 端口接进 `guardedExecuteCommit`，仅在以下**全部满足**后单域（录音 metadata）开启：NoCommit 真机等价=0 ＋ 执行影子字节等价 ＋ 故障注入回滚演练通过 ＋ 重试幂等 ＋ approval/rollback 护栏绿。
4. **观察期后逐域扩展**（音频上传最后）→ UI 读 `CanonicalObjectProjection` → 退役 legacy。

**沿用项（上轮已提，仍建议处理）**：
- 把 3 个 gating 配置（shadow / singleDomain / v8CutoverAppSeam）**收敛成单一"迁移阶段"枚举**，降低误配面。
- 确认 NoCommit 暂存临时根、执行影子根都有清理（磁盘卫生）。

**红线（不变）**：`manifestHash` 永不当鉴权（保 TLS pinning + HMAC）；真实 apply 端口必须 `isInsideRoot` 且原子+可回滚+崩溃安全；保留 Commit 执行器对 dryRun 端口的 fail-closed；默认关、一次一个域、影子/暂存先于提交。
