## 症状 → 真凶(精确)

### 真凶 1：进学习库卡十几秒 + 上传卡顿∝文件大小
- **同一个根因**:`RecordingUploadCoordinator` 是 `@MainActor`(:15),其 `localAudioDecisionState(for:)`(:2019)在主线程**同步**调用 `SecureUploadUtilities.sha256Hex(fileURL: audioURL)`(:2026)——**把整个音频文件读完并哈希**(分块读但仍是全文件、同步)。
- 进学习库:逐个录音算签名 → N 个文件 N 次全文件哈希全在主线程 → **十几秒冻结**。
- 点上传:对该文件算全文件哈希 → **卡顿时间 ∝ 文件大小**。
- 这正是"∝文件大小"的铁证:**主线程上的全文件哈希**。R1(诊断异步)、R2(读缓存)、任务卡1(Mac 服务端)都没碰这条 iPhone 上传协调器路径。

### 真凶 2：点击上传一直失败
- fullSync 下上传走 `IPhoneAudioUploadCutoverExecutor`(`:1234`),其端口由 `canonicalAudioUploadPortFactory(...)`(`:1233`)提供——**而这个工厂给的是禁用桩** `IPhoneCanonicalProductionUploadPort`,它直接 `throw productionMutationAttempted("iphoneProductionUploadDisabled")`(`:239`)。
- 即:canonical "接管"了上传,但它底下的真实上传端口**从来没实现**,是个禁用桩 → **每次上传必败**。

## 修订任务卡 1 · 灭卡顿(把 iPhone 全文件哈希移出主线程 + 缓存)【最高优先】

**文件**：`Rokurics/RecordingUploadCoordinator.swift`(`@MainActor` :15)、`Rokurics/SecureUploadUtilities.swift`、`Rokurics/StudyLibraryStore.swift`
**根因**：`localAudioDecisionState`(:2019)主线程同步 `sha256Hex`(:2026)全文件哈希;进库逐文件、上传时都算。
**做什么**：
1. 把音频签名(sha256 + size)计算**移出主线程**:放后台 actor 或 `Task.detached(priority:.utility)`;`localAudioDecisionState` 改 `async`,调用方 `await`。
2. 加 **size+mtime → sha256 落盘缓存**:文件没变就不重算;进库只读缓存签名,绝不在主线程重哈希。
3. **进库路径**(`StudyLibraryStore.refresh` / `RecordingLibraryView.onAppear`)状态显示改用**缓存签名或 `EffectiveSyncStatus`**,不得逐文件同步哈希。
**验收(真机)**：进学习库**瞬间不卡**(十几秒→即时);大文件上传时主线程不冻结;诊断 `hashDurationMs` 在后台、`mainActorLongTaskDurationMs` 有界。
**不准**：不加新类型;不改安全;不动 oldKernel 默认。

## 修订任务卡 2 · 修上传必败(canonical 上传端口用真实传输,或回退 legacy)

**文件**：`Rokurics/RecordingUploadCoordinator.swift`(`:1233` `canonicalAudioUploadPortFactory`)、`Rokurics/IPhoneCanonicalProductionUploadPort.swift`
**根因**：fullSync 上传走 cutover executor,但工厂给的是禁用桩 `IPhoneCanonicalProductionUploadPort`(`:239` 抛 `iphoneProductionUploadDisabled`)→ 必败。
**做什么(二选一,优先 A)**：
- **A(真接管)**：让 `canonicalAudioUploadPortFactory` 在 fullSync 返回**真实上传端口**——用现成的 `IPhoneCanonicalSecureAudioUploadPort` + `SecureMacUploadClient` 传输(`IPhoneAudioUploadCutoverExecutor` 已有接受 `transport:` 的便利 init),不要再给禁用 production 桩。
- **B(先保可用)**：cutover executor 在端口 disabled 时**回退到 legacy 上传**(原 `SecureMacUploadClient` 直传链路),保证上传成功;canonical 端口待真实实现后再切。
**验收(真机)**：点上传**能成功**(大小文件都成);诊断出现 `finalizeProofAccepted`;不再出现 `iphoneProductionUploadDisabled`。
**不准**：不绕 TLS/HMAC/RequestVerifier;不新增 route;不加新类型。
