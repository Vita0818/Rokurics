## 2. 风险核验（仍为零，且更稳）

- **落地试点入口已接进 app**（iPhone `StudyLibrarySyncCoordinator.swift:2117/3327`、Mac `SecureLocalHTTPSServer.swift:3894/4041`），但**默认关**：`guard configuration.mode.isConfigured …`（`:3335`），而 `canonicalLibraryMetadataDebugPilotConfiguration` 默认 `.disabled`（`SecureReceiverService.swift:263`，coordinator 同构）→ 直接 return nil，什么都不做。
- **真实执行器未注入**：试点调用传 `executor: canonicalLibraryMetadataCutoverExecutor`（`:3366`），该属性默认 `nil`（`SecureReceiverService.swift:264`）；app 入口构造 coordinator/server 不传它 → 取默认。即便试点被设成 arm/execute，无执行器也只能评估、不能 commit。
- **真实写端口工厂仅测试可达**：`LibraryMetadataProductionCanaryBootstrap` 在 app 非测试代码零调用；要它产出非 dryRun 的 production-root 端口，必须显式 `allowProductionRootWrites:true`（app 内零出现）。
- **读路径仍 legacy**：`StudyLibraryStore`/学习库 UI canonical 零命中，本轮未改。
- **冻结护栏是净收益**：`CanonicalMigrationLandingFreeze` 实跑并对"读路径非 legacy / 存在生产注入 / 多试点 / 默认启用 / 其它域非静止"等直接判违规——把上轮我担心的"误配触发未验证真写"做成了**可观测、会报警的自检**。

→ 学习库本轮**没有写真实数据、没有切读、没有注入**；安全态还多了一道实跑护栏。
