# Codex 两张任务卡 · 自动卡顿日志 + 去开关全程新内核

- 时间：2026-06-20 (CST)
- 目的：① 不再手动 sample/grep,让脚本自动产出双端卡顿 Top 报告;② 去掉新旧内核开关,运行时恒为新内核,消除降级歧义。

---

## 任务卡 1 · 卡顿自动日志 + 自动提取(双端 + Mac 自动抓 iPhone)

**硬约束**：不改任何 UI、不改任何同步/业务逻辑——只新增"埋点日志"和"宿主机脚本"。日志走**已有的异步写入器**,绝不在主线程同步写。

**A. 应用内埋点(在 RokuricsShared 写一份,iPhone/Mac 共用——遵循复用原则)**
1. 新增轻量 `CanonicalPerfLog`(SyncCore):给"用户级操作"记起止+总耗时,落到现有 Diagnostics jsonl:
   - 进入学习库(view 出现 → 内容就绪)、立即同步(tap → 完成)、上传(tap → 成/败)。
2. 每条带:`operation` 名、`totalMs`、内部最大子阶段(`inventoryBuildMs / projectionRebuildMs / hashMs / applyMs / waitBackgroundMs`,复用已有 `*DurationMs`)。
3. `totalMs` 超阈值(如 800ms)时,额外写 `phase="jankDetected"` + 主导子阶段名。
4. **关键**:凡 `Task.detached` 跑的重活(哈希/构建/投影/apply)都包一层计时,写进同一条操作日志的子阶段——以便区分"主线程卡"vs"后台慢、UI 干等"(已知现在多半是后者)。

**B. 宿主机脚本(`scripts/jank_report.sh` 或 `.py`,Mac 上跑)**
1. 自动定位 Mac app 的 `connection-diagnostics.jsonl`(排除 `*UITests*`,取最新)。
2. 自动从 **USB 连接的 iPhone** 拉取 app 容器内 Diagnostics jsonl —— 用 `xcrun devicectl device copy from`(或 `pymobiledevice3`)按 bundle id 取 `Documents/Rokurics/Sync/Diagnostics/`。
3. 解析两端,输出**精炼**的"卡顿 Top 报告":按 `totalMs` 降序列出超阈值操作,每行 = 端 + operation + totalMs + 主导子阶段。

**验收**：在 Mac 上重现"进学习库卡 / 立即同步卡 / 上传失败",跑一次 `scripts/jank_report.sh`,自动打印**双端** Top 卡顿(例:`Mac 进入学习库 11200ms 主导=projectionRebuildMs(10800)`),无需手动 sample/grep。
**不准**：改 UI/同步逻辑;主线程同步写日志;新增 sync route。

## 任务卡 2 · 去掉新旧内核开关,全程新内核(保留旧内核代码)

**目标**：运行时**恒为新内核**(canonicalFullSync 行为);**旧内核代码保留不删**,仅作为"canonical 某操作暂不能执行时"的兜底,保证功能不失效。

**做什么**
1. **取消开关与门控降级**:effective 内核恒为 `canonicalFullSync` —— 不再读 AppStorage 的 mode,不再经 `resolve()` 的 readiness/确认门(那些门是自证默认 `true` 的橡皮图章,且可能把 fullSync 悄悄降级回 oldKernel)。直接把 `effectiveConfiguration` 钉死为全 canonical。
2. **去掉设置里**的"内核模式"选择器与"确认开启完整同步"弹窗(允许的 UI 改动,仅此一处)。
3. **保留 legacy 代码**:不删任何 legacy 路径;凡 canonical 端口/执行器目前仍是 stub/disabled 的操作(已知:音频上传 production 端口 `iphoneProductionUploadDisabled`),**自动回退 legacy 执行**,保证功能不失效(上传仍能成)。
4. 切回证明 driver 保留(仍可手动跑);但不再有 oldKernel 运行模式。

**验收**
- 启动即全程新内核;设置无内核开关、无确认门控;日志里 `effectiveMode` 恒为 `canonicalFullSync`,不再降级 oldKernel。
- 功能不退:上传仍能成(canonical 端口 stub 时走 legacy 兜底),读/同步/状态正常;编译零 error;legacy 代码仍在。
**不准**：删除 legacy 代码;绕过 TLS/HMAC/RequestVerifier;新增 route。

> 取舍提示:第 3 步保留 legacy 兜底是为了"上传等暂不可用的 canonical 操作仍能用"。若你想用"上传直接失败"来逼 canonical 上传端口尽快真实化,可去掉上传那条兜底——但那样在 canonical 上传端口实现前,上传会一直失败。建议先留兜底。

---

## 顺序
**先做卡 1**(拿到自动日志工具),**再做卡 2**(全程新内核)。卡 2 落地后,跑卡 1 的脚本,就能直接看到"全程新内核下,双端到底哪个操作、哪个后台阶段在吃十几秒"——以后定位卡顿一条命令搞定,不再手动折腾。
