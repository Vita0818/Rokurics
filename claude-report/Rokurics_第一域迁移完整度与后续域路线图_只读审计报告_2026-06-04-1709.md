3. **读路径仍是 legacy。** 本轮 `RecordingManager`/`AudioFileStore`/录音 UI **未改动**（git status 确认）。即使将来开启 commit，canonical 也只是"写"，app 仍从 legacy 读 metadata——**域的 read 侧尚未迁移**。

### A.3 完整度结论

- **write 路径**：code-complete + 测试验证 + 设计克制（金丝雀/闸门/回滚/防逃逸/原子）→ 完整度高。

## Part B — 后续域迁移路线图（复用第一域验证过的模板）

第一域已经把**单域迁移的可复用模板**跑通。每个后续域按同一八步走：

1. **投影**：该域的真实数据 → canonical 对象（adapter）。
2. **决策**：planner 产出该域 apply 计划（多数已在 `CanonicalApplyPlanner`/`LibrarySyncPlanner` 覆盖）。
3. **NoCommit 执行器**：暂存 + 与 legacy 等价比对（写暂存根，不碰真实根）。
4. **真实根 apply 端口**：原子替换 + 检查点 + 回滚 + `rootEscape` 防逃逸（复用 `CanonicalRootBoundMetadataWriteCore` 模式，但该域专属副作用白名单）。
5. **Commit 执行器**：前/后置校验、幂等、回滚+致命阻断、域专属副作用白名单、故障注入。
6. **app 接缝**：`canaryCommit`（限爆炸半径）+ 闸门 + legacy 回退，**默认关**。
7. **读侧切换**：UI/同步改读 canonical 投影（`CanonicalObjectProjection`），先并行对照差异=0 再切主读。
8. **退役 legacy**：观察期通过 + `CanonicalRetirementReadiness` 达标后，逐域删除 legacy 分支（影子比对再留一段时间作回归闸门）。

**推荐域顺序（按可逆性/爆炸半径，从小到大）**：
录音 metadata（进行中）→ **生成产物（转写/笔记，可重生，最安全）** → 文件夹/学习项 metadata → **tombstone/删除（危险：防复活）** → **录音音频上传（最重：大文件/网络/resumable，放最后）**。

## Part C — 后续域的注意事项（重点防坑）

1. **"读侧迁移"是被低估的另一半。** 第一域的教训：commit 写完≠域迁移完成。每个域都要显式做第 7 步（UI/同步读 canonical），否则会出现"canonical 写、legacy 读"的双真相，反而更易出 bug。**建议把读侧切换列为每个域的硬性验收项。**
2. **每个域需要自己的真实根端口 + 副作用白名单。** 录音 metadata 的端口白名单只允许 metadata 写/路由；**别把它复用到音频上传**——音频是大文件/分块/网络，回滚语义、原子性、爆炸半径都不同，必须重做端口与金丝雀。
3. **删除/tombstone 域要专门防"删除被对端旧数据复活"。** 这是分布式删除的经典坑：提交删除前要确认对端不会用过期 metadata 把它还原；canary 阶段尤其要盯。
4. **跨设备协调。** metadata 的 `send`（`/sync/apply-metadata`）跨设备：开 commit 时，iPhone 发 + Mac 应用要协调（同一域要么单端先行、要么双端同 canary 预算），并验证 Mac 应用幂等、TLS pinning+HMAC 仍走真实校验（影子里 transport 是抑制的，真 commit 要走真实发送，需单独验证）。
5. **"启用"是部署动作，不是写代码。** 模板齐了之后，上线某域 = 在 app 构造处注入真实执行器 + 把 config 设 `canaryCommit`（N=1）→ 真机看诊断 → 逐步放大 N → 再切读侧。**出厂保持默认关，直到该域真机金丝雀验证通过。**
6. **一次只推一个域、一个阶梯档位。** 不要同时开两个域；每个域走 `shadow→executionShadow→NoCommit→guardedExecuteCommit(评估)→canaryCommit(N=1)→放大→读侧→退役`。
7. **故障注入回滚演练是每个域的过门硬条件。** 复用 `CanonicalRecordingMetadataCommitFailureInjection` 那套，对每个域的真实端口做写中断/部分提交/磁盘满/权限失败/回滚失败演练，全绿才放行。
8. **配置旋钮收敛。** 现已有 shadow / singleDomain / v8CutoverAppSeam 等多个门；随域增多会更乱，**建议尽快统一成单一"域 × 阶段"矩阵配置**，避免误配把某域意外推到 commit。
9. **临时根/暂存根清理**（沿用）：执行影子根、NoCommit 暂存根、真实数据副本根都要确认运行后回收。
10. **红线不变**：`manifestHash` 永不当鉴权（保 TLS pinning+HMAC）；真实写必须 `rootEscape` 防逃逸 + 原子 + 可回滚 + 崩溃安全；保留 Commit 对 dryRun 端口 fail-closed；保留 legacy 回退直到读侧迁移 + 观察期过。
