## 2. 新内核可信度

### 2.1 提升可信度的事实（值得肯定）

- **设计诚实、默认安全**：默认关闭、只读、全副作用抑制、诊断做脱敏（`CanonicalShadowMigrationRedaction.safeText`）、失败默认非致命。开启后也不会动你的真实数据。
- **双端对称接缝**：iPhone tick 与 Mac inventory 两侧都接了同一套影子，能对齐两端视角。
- **影子产出真实分歧信号**：比对 canonical 决策 vs 旧 `legacyActionSnapshot`（按域：recordingMetadata/generatedArtifacts/recordingAudio/conflicts/apply），给出 `divergenceCount`。
- **测试是实打实的行为测试，不是同义反复**：抽查 `CanonicalShadowSeamTests`——默认配置断言"**不**产生任何 `canonicalShadowMigrationStarted` 事件"（证明真默认关）；`diagnosticsOnly` 断言产生事件但 `applyMetadataCount==0 / artifactPutCount==0`（证明零副作用）。这类断言验证的是真实行为与边界。
- 测试面广：本轮新增 `CanonicalShadowMigrationTests / CanonicalShadowSeamTests`，叠加既有 facade/adapter/guard/rollback/equivalence 测试。

→ **决策层可信度在稳步上升，而且现在第一次"可被真机验证"**（把影子设为 diagnosticsOnly→dryRunCompare→shadowReadOnly，在真机收集分歧）。

### 2.2 仍未被验证、需警惕的点（防止过度信任）

1. **影子只证明"决策等价"，不证明"执行正确"。** app 影子用 dry-run 端口 + 已构建清单，真实写盘/上传/传输适配器**一次没在 app 跑过**。**"影子分歧=0"≠"切过去能用"**——这是最容易踩的信任陷阱。
2. **影子复用 `inventory.canonicalManifest`（同一套投影适配器产出）。** 所以它覆盖的是"canonical planner vs legacy planner 在同一清单上的差异"，对"投影 vs 真实数据"的偏差只能部分覆盖（哈希类偏差会显形，但系统性但自洽的投影错误未必显形）。即影子是**决策级**对照，不是**地面真值**对照。
3. **app 内不存在任何真实执行路径**：最激进的模式也是 `shadowReadOnly`，且 `executeProduction` 仍锁死在 `nodeRole == .testHarness`。所以"执行可信度"在真实环境里**结构性地无法被采集**——只能靠测试 harness 的结论，而 harness 用的是测试根/内存/假传输。
4. **真机表现尚未纳入**（你之前也明确表示先不看表现）；但要注意：决策等价不代表性能/卡顿/时序在真机可接受。

### 2.3 可信度分层结论

| 层 | 可信度 | 依据 |
| --- | --- | --- |
| 数据模型 / 投影契约 | 较高 | 大量单测 + 路径安全 + 单一投影契约 |
| 决策（sync/apply/library planner） | 上升，且**现可真机验证** | 行为测试 + 双端影子接缝 + 分歧遥测 |
| 执行 / 运行时（文件/上传/传输/apply 写回） | **未在任何真实场景验证** | 真实适配器仅测试可达；app 影子为 dry-run、零副作用 |
| 端到端迁移安全 | 未验证 | 无执行影子、无受控 on-device 执行、无切主演练 |

## 3. 给你的判断与下一步（仅建议，未改任何代码）

**可信度建设建议**——用本轮的影子把"决策层"打成可信，并明确它的边界：

1. **现在就能做**：真机把 `canonicalShadowMigrationConfiguration` 依次设 `diagnosticsOnly → dryRunCompare → shadowReadOnly`，在你的真实库上收集 `divergenceCount` 与等价报告；以"分歧持续为 0"作为**决策层**信任门槛。
2. **别据此切换**：决策层影子绿，只允许你信任"canonical 决策与旧逻辑一致"。**执行层仍是未知数。**
3. **要建立执行层可信度，下一轮需要**：把影子端口从 dry-run 换成**真实存储/真实传输适配器**（FilePort 接真实录音根、Transport 走真实 TLS+HMAC 的只读探针、Upload 接真实 resumable），在**真实数据的影子副本**上做"执行影子"并比对结果；同时把 `executeProduction` 从 testHarness 硬锁放宽为"受控、默认关、可回滚"的 on-device 影子角色。
4. **切主前置闸门**：决策分歧=0 **且** 执行影子结果一致 **且** 回滚演练通过 **且** 护栏 reject 清零。缺任一项都不应切。
